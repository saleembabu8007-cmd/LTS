# LTSGROUP WEBSITE — MASTER PRODUCT DESIGN & ENGINEERING RULES

You are working on the existing LTSGROUP corporate website.

IMPORTANT:
This is NOT a redesign-from-scratch project.

The existing website already has a strong visual foundation. Your job is to systematically improve, refine, standardize and complete it into a polished production-ready corporate website.

Do not throw away the current visual direction.

Do not replace the existing design with a generic corporate website.

Do not introduce a new visual identity.

==================================================
1. PRIMARY OBJECTIVE
==================================================

Transform the current LTSGROUP website into a polished, highly consistent, production-ready engineering and construction corporate website.

The result must feel:

- established
- technically credible
- premium
- architectural
- precise
- restrained
- modern
- trustworthy
- editorial
- corporate
- easy to navigate

It must NOT feel:

- like a SaaS dashboard
- like a startup landing page
- like a generic AI-generated website
- like a template
- over-designed
- excessively animated
- full of floating cards
- full of gradients
- visually noisy
- unnecessarily futuristic

==================================================
2. SOURCE OF TRUTH
==================================================

The supplied LTSGROUP master company information document is the source of truth for company facts.

Use only information established in the supplied material.

Do NOT invent:

- company history
- founding year
- leadership
- employee numbers
- project numbers
- revenue
- certifications
- awards

- locations
- clients
- project values
- technical capabilities
- industries
- statistics

External websites are design/UX references only.

Never copy external company facts into LTSGROUP.

==================================================
4. VISUAL FOUNDATION
==================================================

Preserve the current LTSGROUP visual direction.

Primary visual characteristics:

- deep navy hero/footer
- white and warm-neutral content surfaces
- architectural blue
- restrained accent colors
- thin borders
- soft intentional corners
- editorial typography
- large photography
- strong grid
- asymmetric compositions where useful
- generous whitespace
- compact technical metadata
- restrained capsule controls

Do not introduce:

- glassmorphism
- excessive shadows
- neon effects
- excessive gradients
- giant decorative typography
- excessive rounded cards
- floating SaaS-style UI
- random blobs
- decorative 3D objects
- unnecessary illustrations

==================================================
5. DESIGN TOKEN RULE
==================================================

Use a centralized design token system.

Do not create one-off values inside individual components unless genuinely necessary.

Centralize:

- colors
- typography
- spacing
- radii
- borders
- container widths
- breakpoints
- button sizes
- shadows
- animation timings

The current atomic design specification should remain the foundation.

Important visual rules from the current system:

- large feature media: approximately 32–36px radius
- standard image: approximately 28px
- content surface: approximately 24px
- buttons/small UI: approximately 12–16px
- restrained capsule controls
- zero or extremely subtle shadows
- depth primarily through photography, spacing and borders

==================================================
6. TYPOGRAPHY
==================================================

Typography must feel architectural and editorial.

Use the existing project typography system.

Do not introduce many font families.

Hierarchy should be:

Display
→ Page title
→ Section heading
→ Card heading
→ Body
→ Metadata
→ Eyebrow / technical label

Headings should be strong but not oversized.

Avoid:

- huge 100px+ marketing headings
- excessive bold text
- long paragraphs
- center-aligning everything

==================================================
7. LAYOUT
==================================================

Use a consistent global container.

Recommended desktop principles:

- wide centered container
- approximately 72–80px horizontal breathing room on large screens
- consistent max-width
- 12-column grid where useful
- controlled asymmetric layouts
- predictable vertical rhythm

Do not make every section full-width.

Do not make every section a card.

Use three visual levels:

1. Open editorial sections
2. Image-led feature compositions
3. Structured content surfaces

==================================================
8. IMAGE RULES
==================================================

Photography is a major part of the LTSGROUP identity.

Use images intentionally.

Prefer:

- engineering environments
- MEP systems
- buildings
- infrastructure
- technical installations
- facilities
- equipment
- construction environments
- architecture
- people only when contextually useful

Avoid:

- generic corporate handshake photos
- obviously AI-generated people
- cheesy stock imagery
- excessive blue overlays
- excessive darkening
- inconsistent image treatment

Images should feel authentic and technically relevant.

==================================================
9. IMAGE CARDS
==================================================

Image-based cards are approved and should be improved rather than removed.

Use:

- large editorial image cards
- image + title overlays when appropriate
- image + metadata
- image + short description
- project cards
- service cards
- industry cards

But do not make every section a card grid.

Mix:

- 1 large feature + smaller items
- 2-column editorial layouts
- horizontal cards
- image + text splits
- project mosaics
- simple lists

==================================================
12. CONTENT PRINCIPLES
==================================================

Content must be concise.

Do not write marketing fluff.

Do not add paragraphs just to fill space.

Prefer:

short headline
+
one concise supporting sentence
+
clear CTA

Use technical language when appropriate.

Avoid phrases like:

"revolutionary"
"world-class"
"cutting-edge"
"next-generation"
"unparalleled"

unless supported by official content.

==================================================
13. PAGE PRINCIPLE
==================================================

Each page must have a clear narrative.

A page should NOT be:

Hero
random cards
random image
random statistics
random CTA

Instead:

Context
→ capability
→ evidence
→ detail
→ proof
→ next action

==================================================
14. UX PRINCIPLE
==================================================

The user should understand the website within seconds.

Navigation should clearly communicate:

What LTSGROUP does
Where its services are
What projects it has
Who it serves
How to contact it

Do not hide important information behind excessive interaction.

==================================================
15. MOTION
==================================================

Motion is supporting content, not decoration.

Use:

- 150–250ms UI transitions
- approximately 300–500ms editorial media transitions
- subtle image scale
- opacity
- translate
- accordion transitions

Avoid:

- parallax everywhere
- scroll-jacking
- dramatic reveals
- excessive movement
- continuous animation

Respect prefers-reduced-motion.

==================================================
16. RESPONSIVE
==================================================

The website must be intentionally designed for:

Desktop
Tablet
Mobile

Do not simply shrink desktop.

On mobile:

- preserve hierarchy
- reduce complexity
- stack intelligently
- maintain image impact
- maintain readable typography
- simplify navigation
- avoid horizontal overflow

==================================================
17. ACCESSIBILITY
==================================================

Maintain:

- semantic HTML
- keyboard navigation
- visible focus states
- accessible buttons
- accessible forms
- sufficient contrast
- meaningful alt text
- reduced-motion support
- proper heading hierarchy

==================================================
18. ENGINEERING RULE
==================================================

Before modifying anything:

1. inspect the existing repository
2. understand the current architecture
3. identify existing reusable components
4. identify duplicate components
5. identify existing design tokens
6. identify routing
7. identify data structures
8. identify image handling
9. identify responsive logic

Do not rewrite working infrastructure unnecessarily.

==================================================
19. IMPLEMENTATION RULE
==================================================

Work incrementally.

For every major task:

1. inspect
2. plan
3. implement
4. run/build
5. visually verify
6. fix inconsistencies
7. continue

Never assume a section is finished simply because it compiles.

==================================================
20. FINAL QUALITY BAR
==================================================

The final website should look like it was designed and engineered by a highly experienced corporate digital design team.

The standard is:

"Could this be published as the official website of an established UAE engineering company?"

If the answer is no, refine it.

Do not optimize for quantity of sections.

Optimize for:

clarity
consistency
credibility
usability
visual quality
content hierarchy
technical polish
