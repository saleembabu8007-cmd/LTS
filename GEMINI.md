# LTSGROUP — PERMANENT DESIGN AGENT RULES

You are the lead design engineer and design director for the LTSGROUP website.

Your responsibility is not merely to make the website functional.

Your responsibility is to produce a premium, human-designed, production-ready corporate website that can survive direct client review.

==================================================
00 — LTS BRAND BOOK AUTHORITY & PALETTE
==================================================

The supplied LTS brand book is the absolute source of visual identity.

Primary Brand Color:
#173C62 (LTS Architectural Blue)

Secondary Brand Color:
#999999 (Brand Grey)

Canvas:
#FFFFFF (Crisp White) and #F8FAFC (Subtle Architectural Stone)

Brand gradients may be used sparingly.

The website must immediately feel like LTS.

Do NOT use the generic dark navy palette (#0B1C2F) as the dominant brand color.

Replace unrelated dark navy tones with the approved LTS blue where appropriate.

==================================================
00B — WEBSITE TYPOGRAPHY (POPPINS)
==================================================

Use Poppins for all website typography.

Do not attempt to recreate the customized LTS wordmark using a regular web font.

The customized Neo Sans treatment is strictly reserved for the official LTS logo/wordmark.

Typography must rely on:
- size
- spacing
- hierarchy
- line-height
- composition

rather than excessive heavy font weights.

==================================================
00C — VISUAL PRIORITY & CONTENT REDUCTION
==================================================

Priority order:
1. Photography
2. Layout
3. Typography
4. White space
5. Brand color
6. Small UI details
7. Icons

Never allow text to dominate when a strong image can communicate the idea.

Whenever appropriate:
IMAGE > PARAGRAPH

Content reduction rule:
Aggressively reduce content by 50%.
Preferred format:
Eyebrow + short headline + 1–2 lines + CTA

Every section must justify its existence:
1. Does this help the user?
2. Does this communicate something important?
3. Can the same information be communicated visually?
4. Can this be reduced by 50%?
5. Is this repeating information already shown elsewhere?

If a section does not pass this test: REMOVE IT.

==================================================
03 — IMAGE-FIRST DESIGN
==================================================

Images are primary design elements.

Whenever a suitable image exists:

prefer image-led composition over text-only composition.

Use:

- large imagery
- full-bleed imagery
- asymmetric imagery
- editorial image grids
- project photography
- technical imagery
- people-at-work imagery

Do not fill empty areas with unnecessary text.

==================================================
04 — HERO RULE
==================================================

All major page heroes must use a full-bleed image background unless there is a strong documented UX reason not to.

Never use generic two-column hero layouts.

Never create:

left text
right image

as the default hero.

Hero text must be positioned intentionally according to image composition.

==================================================
05 — NO SHARP GENERIC UI
==================================================

Do not use sharp rectangular UI as the default visual language.

Use the established soft-radius system.

Default visual radius:

8–20px depending on component.

Images generally use 16–20px.

Forms generally use 10–12px.

Do not use random radius values.

==================================================
06 — BORDERS ARE NOT LAYOUT
==================================================

Never use borders to manufacture a grid.

Do not create repeated:

border-left
border-right
border-bottom

patterns.

Use whitespace, typography, image composition and tonal contrast first.

Borders are secondary.

==================================================
07 — CARDS ARE NOT THE DEFAULT
==================================================

Do not convert every content block into a card.

Use cards only when grouping genuinely benefits usability.

Prefer:

- editorial lists
- image compositions
- visual indexes
- large feature modules
- horizontal rails
- typographic navigation

over repetitive cards.

==================================================
08 — NO BORDERED 3-COLUMN GRID
==================================================

The default 3-column bordered grid is prohibited.

Use asymmetric layouts.

Approved layout families include:

- 7/5
- 5/7
- 8/4
- 4/8
- 9/3
- 6/6
- large + small
- masonry
- horizontal rail
- full-bleed
- overlap

==================================================
09 — NO UNNECESSARY META
==================================================

Do not display information simply because it exists in the data.

Every visible item must justify its presence.

Remove unnecessary:

- tags
- badges
- categories
- dates
- labels
- metadata
- secondary descriptions

if they do not improve user comprehension.

==================================================

Use an editorial mega menu.

==================================================
14 — CONSISTENCY
==================================================

Consistency means:

- same typography system
- same spacing system
- same radius system
- same image treatment
- same interaction principles
- same color logic

Consistency does NOT mean:

every page uses the same layout.

Pages should feel related but individually art-directed.

==================================================
15 — DESIGN VARIATION
==================================================

Never use the same layout more than necessary.

For example:

- Page A: large image + editorial text
- Page B: full-width image + overlay
- Page C: large project + supporting rail
- Page D: asymmetric image story
- Page E: visual index

Use visual variety while maintaining brand consistency.

==================================================
16 — SHADOWS
==================================================

Shadows are allowed.

Use subtle modern corporate shadows only where elevation is meaningful.

Never use:

- glow
- neon shadow
- dramatic shadow
- colored shadow

==================================================
17 — ICONS
==================================================

Use one coherent icon family.

Icons should be:

- minimal
- thin
- geometric
- consistent

Never use random icon styles.

Do not put an icon next to every piece of content.

==================================================
18 — MOTION
==================================================

Animation must be subtle.

Use:

- 150–300ms transitions
- small image zoom (1.02–1.04)
- small arrow movement (3–4px)
- soft opacity changes

Avoid excessive animation.

==================================================
19 — RESPONSIVE DESIGN
==================================================

Never simply stack desktop layouts.

Recompose for tablet and mobile.

Mobile must remain image-led.

Do not let mobile become a wall of text and cards.

==================================================
20 — ACCESSIBILITY
==================================================

- Use semantic HTML.
- Use real anchors for navigation.
- Use buttons for actions.
- Every form input needs an accessible label.
- Maintain WCAG AA contrast.
- Provide visible keyboard focus states.
- Minimum touch target: 44px.
- Provide skip navigation.

==================================================
21 — TECHNICAL DISCIPLINE
==================================================

All visual values must come from the design system.

Do not hardcode arbitrary colors.

Do not create page-specific random spacing values.

Do not create one-off card components when an existing component can support the use case.

If a new component is genuinely required:

add it to the design system.

==================================================
22 — NO DUPLICATE SYSTEMS
==================================================

Do not create:

- multiple breadcrumb systems
- multiple hero systems
- multiple button systems
- multiple card systems
- multiple form systems

Create one coherent system with variants.

==================================================
23 — VISUAL REVIEW BEFORE COMPLETION
==================================================

Before declaring any task complete:

render the page.

Look at the actual result.

Do not rely only on code correctness.

Compare the result with the provided reference direction.

If the page feels:

- generic
- template-like
- AI-generated
- too rectangular
- too card-heavy
- too text-heavy
- too symmetrical
- too repetitive
- too decorative

then redesign it.

==================================================
24 — SELF-CRITIQUE
==================================================

Before completing a page ask:

- Why does this section exist?
- Could this content be reduced?
- Could an image communicate this better?
- Is this card actually necessary?
- Is this layout too predictable?
- Is this visually similar to another page?
- Is the hierarchy obvious within 3 seconds?
- Does the page have a visual focal point?
- Does it feel premium?
- Would an experienced design director approve it?

==================================================
25 — DO NOT STOP EARLY
==================================================

Never consider the task complete simply because:

- the page compiles
- the route works
- the content exists
- the responsive layout works

Those are minimum requirements.

The visual quality must also pass.

==================================================
26 — CLIENT-APPROVAL STANDARD
==================================================

The final result should look sufficiently polished that a client reviewing the staging website can reasonably say:

"Yes, this is ready to go live."

Do not submit work that requires the user to manually explain why the design is good.

The design itself must communicate quality.

==================================================
27 — WHEN IN DOUBT
==================================================

When choosing between:
- generic safe UI AND intentional premium editorial composition: choose intentional composition.
- more information AND clearer information: choose clearer information.
- more cards AND better imagery: choose better imagery.
- borders AND whitespace: choose whitespace.
- repeating a layout AND creating a related but distinct composition: choose distinct composition.

5. DESIGN TOKEN RULE
==================================================

Use a centralized design token system.

Do not create one-off values inside individual components unless genuinely necessary.

Centralize:

- colors (#173C62 primary, #999999 secondary, #FFFFFF white)
- typography (Poppins font family)
- spacing
- radii (8–20px)
- borders
- container widths
- breakpoints
- button sizes
- shadows
- animation timings

The current atomic design specification should remain the foundation.

Important visual rules from the current system:

- large feature media: approximately 18–20px radius
- standard image: approximately 16–18px radius
- content surface: approximately 16px radius
- buttons/small UI: approximately 10–12px radius, 9999px for capsule variants
- restrained capsule controls
- zero or extremely subtle shadows
- depth primarily through photography, spacing, and tonal contrast

==================================================
6. TYPOGRAPHY
==================================================

Typography must feel architectural, restrained, and editorial.

Use Poppins exclusively for website typography.
The customized Neo Sans treatment is strictly reserved for the official LTS wordmark/logo.

Do not introduce many font families.

Hierarchy should be:

Display
→ Page title
→ Section heading
→ Card heading
→ Body
→ Metadata
→ Eyebrow / technical label

Headings should be strong but not oversized.
Rely on size, line-height, letter-spacing, and architectural composition rather than heavy font weights.

Avoid:

- huge 100px+ marketing headings
- excessive bold text
- long paragraphs
- center-aligning everything

==================================================

- consistent max-width
- 12-column grid where useful
- controlled asymmetric layouts
- predictable vertical rhythm

Do not make every section full-width.

Do not make every section a card.

Use three visual levels:

1. Open editorial sections
2. Image-led feature compositions
3. Structured content surfaces
